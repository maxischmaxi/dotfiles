fallstricke

an echtem typescript-code gegen die parser-queries geprüft. genau diese fünf punkte kosten anfangs die meiste zeit.

i= greift nur eine seite

bei let summe = 0; matcht i= sowohl summe als auch 0 — welche seite du bekommst, hängt davon ab, wo der cursor steht. für gezielten zugriff nimm iL und iR, für die ganze anweisung a=.

✓ an der query verifiziert

a= nur bei deklarationen

in typescript erfasst die query const- und let-deklarationen. eine reine neuzuweisung wie summe = summe + 1; ist kein match — dort passiert nichts.

✓ an der query verifiziert

io fehlt in typescript

comment.inner gibt es nur für lua und python. in ts, js, rust, c und c++ funktioniert nur ao — das nimmt die // mit.

✓ über alle parser geprüft

aa räumt das komma mit weg

das ist der eigentliche gewinn: daa löscht container, und hinterlässt eine gültige argumentliste. dia löscht nur den namen und lässt dir ein doppeltes komma.

✓ an der query verifiziert

der cursor muss nicht drin sein

lookahead ist aktiv: steht der cursor vor der funktion, springt cif vorwärts zur nächsten. du musst nicht erst hinnavigieren — das spart die halbe arbeit.

✓ in deiner config gesetzt

af und ac sind zeilenweise

beide sind auf selection_modes = "V" gesetzt. vaf markiert also volle zeilen, nicht ab spalte 1 — genau richtig zum verschieben, aber ungewohnt wenn du zeichenweise erwartest.

✓ in deiner config gesetzt

springen und tauschen

bewusst ohne [ und ] gelegt — auf deutschem layout wären die zwei AltGr-griffe pro sprung.
